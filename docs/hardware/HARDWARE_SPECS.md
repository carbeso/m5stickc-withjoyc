# M5StickC Plus 與 MiniJoyC 硬體規格與開發參考手冊

本文件彙整 **M5StickC Plus** 核心開發板與 **MiniJoyC HAT** 搖桿擴充底座之硬體規格、腳位映射、I2C 通訊協議與暫存器定義，專門作為後續開發**掌上型紓壓玩具 (Stress Relief / Fidget Toy)** 的核心硬體參考依據。

---

## 1. 系統整體架構

本紓壓玩具採用「主核心 + 協同底座」的雙晶片架構：
- **主核心 (Master)**：M5StickC Plus（搭載 ESP32-PICO-D4），負責主要遊戲邏輯、LCD 彩色畫面繪製、六軸姿態運算、蜂鳴器音效控制與電源管理。
- **擴充底座 (Slave)**：MiniJoyC HAT（搭載 STM32F030F4P6），透過 I2C（位址 `0x54`）提供雙軸類比搖桿讀取、搖桿中心微動按鍵偵測、獨立 SK6812 全彩 RGB LED 效果，並自帶 200mAh 鋰電池輔助供電。

```
+-------------------------------------------------------------+
|                      M5StickC Plus                          |
|  [ESP32-PICO-D4 240MHz]                                     |
|  ├── 1.14" 135x240 ST7789v2 TFT LCD (視覺動畫/UI)           |
|  ├── MPU6886 6軸 IMU (晃動/傾斜/手勢偵測)                  |
|  ├── 無源蜂鳴器 Passive Buzzer (機械敲擊聲/音效)             |
|  ├── AXP192 電源管理 + 120mAh 鋰電池                        |
|  ├── Button A (正面大鍵) & Button B (側面功能鍵)            |
|  └── 頂部 8-Pin HAT 擴充槽 (I2C 通訊)                       |
+------------------------------┬------------------------------+
                               │ I2C Bus (SDA: G0, SCL: G26)
+------------------------------┴------------------------------+
|                       MiniJoyC HAT                          |
|  [STM32F030F4P6 協同處理器 @ I2C 0x54]                     |
|  ├── 雙軸類比搖桿 (XY軸 最大偏角 23°, 10kΩ, 8/10/12-bit)    |
|  ├── 搖桿中心按鍵 (Click Switch)                            |
|  ├── SK6812 3535 全彩 RGB LED (動態氛圍光/按壓回饋)         |
|  └── 內建 200mAh 鋰電池 (增加掌上型便攜續航)                |
+-------------------------------------------------------------+
```

### 3.2 I2C 暫存器映射手冊 (Register Map @ 0x54)

MiniJoyC 內部 STM32 韌體已將搖桿採樣、濾波與校正處理完畢，主機（ESP32）透過 I2C 直接讀取暫存器：

| 暫存器位址 | 暫存器名稱 | 長度 (Bytes) | 讀寫屬性 | 格式與數值範圍 | 功能說明 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `0x00` | **ADC_X_REG** | 2 | R (唯讀) | 無號 12-bit (`0 ~ 4095`) | 搖桿 X 軸原始 ADC 採樣值 (低位元組在前) |
| `0x02` | **ADC_Y_REG** | 2 | R (唯讀) | 無號 12-bit (`0 ~ 4095`) | 搖桿 Y 軸原始 ADC 採樣值 (低位元組在前) |
| `0x10` | **POS_X_10BIT** | 2 | R (唯讀) | **有號 10-bit (`-512 ~ 511`)** | 已校正的 X 軸 10 位元偏移量，**中心靜止約為 0** |
| `0x12` | **POS_Y_10BIT** | 2 | R (唯讀) | **有號 10-bit (`-512 ~ 511`)** | 已校正的 Y 軸 10 位元偏移量，**中心靜止約為 0** |
| `0x20` | **POS_X_8BIT** | 1 | R (唯讀) | **有號 8-bit (`-128 ~ 127`)** | 已校正的 X 軸 8 位元偏移量，**中心靜止約為 0** |
| `0x21` | **POS_Y_8BIT** | 1 | R (唯讀) | **有號 8-bit (`-128 ~ 127`)** | 已校正的 Y 軸 8 位元偏移量，**中心靜止約為 0** |
| `0x30` | **BUTTON_REG** | 1 | R (唯讀) | `0` 或 `1` | 搖桿中心按鍵狀態：`0` = 放開，`1` = 按下 |
| `0x40` | **RGB_LED_REG** | 3 | W (唯寫) | `[Red, Green, Blue]` | SK6812 RGB 色彩資料 (RGB888 格式) |
| `0x50` ~ `0x5B` | **CAL_REG** | 12 | R/W | 6 組 16-bit 參數 | 搖桿校正參數：X_min, X_max, Y_min, Y_max, X_cen, Y_cen |
| `0xFE` | **FW_VER_REG** | 1 | R (唯讀) | 1 Byte | STM32 內部韌體版本號 |
| `0xFF` | **I2C_ADDR_REG**| 1 | R/W | 1 Byte | 變更 MiniJoyC 的 I2C 設備位址 (預設 `0x54`) |

> [!IMPORTANT]
> **數值正負方向重要提醒**：
> `POS_X_10BIT`、`POS_Y_10BIT`、`POS_X_8BIT`、`POS_Y_8BIT` 均為**有號數 (Signed Integer)**，中心點為 `0`。在程式中接收時，請務必宣告為 `int16_t` 或 `int8_t` 進行型別轉換；若宣告為無號數 (`uint8_t` / `uint16_t`)，往負方向推動時會造成負溢位（變成 `255` 或 `65535`），導致搖桿瞄準與物理小球運動產生嚴重錯誤。

## 4. 關鍵資源與腳位衝突防呆指南

在 M5StickC Plus 與 MiniJoyC HAT 整合時，有以下數點硬體限制與衝突防呆必須嚴格遵守：

### 4.1 雙 I2C 匯流排分工 (重要)
- **內部 I2C (Wire1)**：
  - 接腳：`SDA = GPIO 21`, `SCL = GPIO 22`。
  - 掛載元件：AXP192 (`0x34`)、MPU6886 (`0x68`)、BM8563 (`0x51`)。
  - 初始化：`M5.begin()` 自動初始化或手動呼叫 `Wire1.begin(21, 22)`。
- **頂部擴充 I2C (Wire)**：
  - 接腳：`SDA = GPIO 0`, `SCL = GPIO 26`。
  - 掛載元件：MiniJoyC HAT (`0x54`)。
  - 初始化：`Wire.begin(0, 26, 400000)` 或使用 `M5HatMiniJoyC::begin(&Wire, 0x54, 0, 26, 400000)`。
  - **防呆重點**：切勿將內部元件與 MiniJoyC 混在同一條 Wire 匯流排上，必須雙匯流排分開獨立操作。

### 4.2 GPIO 0 之物理級衝突與開機保護
- **與 SPM1423 麥克風之硬體互斥**：
  - M5StickC Plus 內建 SPM1423 麥克風的時脈腳 (CLK) 連接至 `GPIO 0`。
  - 頂部 HAT 槽的 I2C SDA 同樣使用 `GPIO 0`。
  - **重要警示**：若啟動 PDM 麥克風採樣，I2S 硬體將輸出高達 1MHz~3.2MHz 的高頻時脈，這會徹底摧毀 I2C 通訊，導致 MiniJoyC STM32 韌體接收逾時、匯流排死鎖。因此在啟用 MiniJoyC 時，**絕對嚴禁啟動 SPM1423 麥克風**。
- **ESP32 開機 Strapping Pin 風險**：
  - `GPIO 0` 同時為 ESP32 的開機模式選擇腳（Strapping Pin）。開機當下若 GPIO 0 處於低電位，ESP32 將進入 UART 韌體下載模式 (Bootloader)，導致程式無法正常開機。
  - MiniJoyC 板上有 4.7kΩ 上拉電阻至 3.3V，正常情況下為高電位；但需注意開機瞬間不要強行短路 SDA 到接地。

### 4.3 GPIO 36 與 GPIO 25 之互斥設定
- StickC Plus 內部電路設計中，`GPIO 36` 與 `GPIO 25` 共用同一個內部類比通道。
- 若程式中需使用 `GPIO 36` 作為 ADC 採樣，必須強制將 `GPIO 25` 設定為浮空（無上下拉）：
  ```cpp
  pinMode(36, INPUT);
  gpio_pulldown_dis(GPIO_NUM_25);
  gpio_pullup_dis(GPIO_NUM_25);
  ```

## 5. 空間方向、搖桿與重力加速度 (IMU) 座標系統對齊手冊

在開發涉及搖桿導覽、體感控制與物理運動（如沙盤模擬、彈珠迷宮、俄羅斯方塊）時，**「搖桿極性、IMU 加速度反作用力與螢幕像素座標」三者之間的映射關係極易搞混**。本節提供精確的硬體視圖、數值定義、極性對照表與防呆轉換公式，避免後續開發踩雷。

### 5.1 基準姿態與硬體空間視圖 (持握視角)

專案預設採用**直向模式** (`M5.Lcd.setRotation(0)`)，螢幕解析度為 **135 (寬, X) × 240 (高, Y)**。
MiniJoyC HAT 擴充槽位於機身頂部，正面下方為 Button A，底部為 Type-C。

```text
                     [ MiniJoyC HAT 頂部 ]
                  +-------------------------+
                  |         [搖桿]          |  <- 向上推 (Up: joyY < 0)
                  |     (中心按鍵 Click)    |
                  |  向左 (Left)   向右     |
                  |  (joyX < 0)  (joyX > 0) |
                  |       向下 (Down)       |
                  |       (joyY > 0)        |
                  |         (RGB)           |
                  +-------------------------+
                  |       8-Pin Header      |
                  +-------------------------+
                  |  M5StickC Plus (0,0)    |  <- 螢幕原點 (X=0, Y=0)
                  | ┌─────────────────────┐ |
                  | │  ST7789v2 LCD       │ |     X 軸向右增加 (0 -> 134)
                  | │  (135 x 240)        │ |  ───────> +X
                  | │                     │ |  │
                  | │                     │ |  │  Y 軸向下增加 (0 -> 239)
                  | │                     │ |  ▼
                  | │                     │ |  +Y
                  | └─────────────────────┘ |
                  |       [Button A]        |  <- 正面大按鍵 (GPIO 37)
                  |       [ M5 標誌 ]       |
                  +-------------------------+
                     [ Type-C 底部 (底端) ]
```

### 5.2 螢幕像素座標系 (ST7789v2 @ Rotation 0)
- **座標原點 (0, 0)**：位於螢幕左上角（靠近 MiniJoyC 的左側）。
- **螢幕 X 軸**：水平向右為正 (`0` 至 `134`)。
- **螢幕 Y 軸**：垂直向下為正 (`0` 至 `239`)。
- **移動向量直覺原則**：
  - 向上移動物件：`y -= speed`
  - 向下移動物件：`y += speed`
  - 向左移動物件：`x -= speed`
  - 向右移動物件：`x += speed`

### 5.3 MiniJoyC 雙軸搖桿方向與極性定義

#### (1) STM32 原始暫存器 vs 專案 InputManager 轉換
MiniJoyC 的 STM32 韌體採樣搖桿電位分壓：
- 原始暫存器 `POS_X` (`0x20`)：向右推為正 (`> 0`)，向左推為負 (`< 0`)。
- 原始暫存器 `POS_Y` (`0x21`)：**向上推為正，向下推為負**（典型笛卡兒座標系）。

> [!CAUTION]
> **重要極性陷阱：Y 軸反轉！**
> 在螢幕像素繪圖系統中，「向下」才是 Y 增加；若直接使用原始 `POS_Y`，會造成「向上推 Y 變大（物件往下跑）」的嚴重反直覺問題。
> 因此專案中的 `InputManager` 在採樣時已強制進行 **Y 軸取負號校正**：
> ```cpp
> joyX = (int8_t)_joyc.getPOSValue(POS_X, _8bit);
> joyY = -((int8_t)_joyc.getPOSValue(POS_Y, _8bit)); // 取負號以符合螢幕座標向下為正
> ```

#### (2) InputManager 統一後的數值標準
經過 `InputManager` 統一後，數值方向與螢幕像素完全同步：
| 推動方向 | `joyX` 範圍 | `joyY` 範圍 | 觸發旗標 (Edge / Hold) | 建議物件位移 |
| :--- | :--- | :--- | :--- | :--- |
| **向上推 (Up)** | `-15 ~ +15` (死區內) | **`joyY < -55` (負值)** | `joyPushedUp` / `isJoyPushedUp` | `y -= speed` (螢幕向上) |
| **向下推 (Down)** | `-15 ~ +15` (死區內) | **`joyY > +55` (正值)** | `joyPulledDown` / `isJoyPulledDown` | `y += speed` (螢幕向下) |
| **向左推 (Left)** | **`joyX < -55` (負值)** | `-15 ~ +15` (死區內) | `joyPushedLeft` | `x -= speed` (螢幕向左) |
| **向右推 (Right)** | **`joyX > +55` (正值)** | `-15 ~ +15` (死區內) | `joyPushedRight` | `x += speed` (螢幕向右) |
| **置中靜止 (Center)**| `-15 ~ +15` (已濾為 0) | `-15 ~ +15` (已濾為 0) | `joyReleased` (回彈邊緣) | 不動 |

### 5.4 MPU6886 加速度計 (IMU) 重力響應與物理映射

M5StickC Plus 內部焊接了 MPU6886 六軸感測器，透過 `M5.Imu.getAccelData(&ax, &ay, &az)` 讀取加速度（單位為 $g$，正常重力為 $1.0g$）。

> [!WARNING]
> **關鍵物理陷阱：加速度計量測的是「支撐反作用力」而非單純重力！**
> 當裝置受地球重力吸引時，內部微機電 (MEMS) 感測器測得的加速度向量是朝向支撐物推擠的反方向。這會導致軸向極性與視覺直覺相反，必須特別注意：
> 1. **機身向左傾斜時**，測得的 `ax > 0`（正值）。
> 2. **機身向右傾斜時**，測得的 `ax < 0`（負值）。
> 3. **機身直立正放時（頭頂搖桿朝上）**，測得的 `ay > 0`（約 `+1.0g`）。
> 4. **機身倒立時（頭頂搖桿朝下）**，測得的 `ay < 0`（約 `-1.0g`）。
> 5. **機身正面平放於桌面（螢幕朝天）**，測得的 `az ≈ -1.0g`。

#### (1) 機身姿態與加速度讀值對照表
| 機身實體姿態 | `ax` 讀值 | `ay` 讀值 | `az` 讀值 | 重力方向直覺判斷 |
| :--- | :--- | :--- | :--- | :--- |
| **正面朝天水平平放** | $\approx 0.0g$ | $\approx 0.0g$ | $\approx -1.0g$ | 平衡靜止，無水平重力分量 |
| **螢幕朝下反面平放** | $\approx 0.0g$ | $\approx 0.0g$ | $\approx +1.0g$ | 趴在桌上 |
| **正立手持 (頭頂朝天，直向)** | $\approx 0.0g$ | **$\approx +1.0g$** | $\approx 0.0g$ | 重力朝向機身底部 (Button A 方向) |
| **倒立手持 (頭頂朝地)** | $\approx 0.0g$ | **$\approx -1.0g$** | $\approx 0.0g$ | 重力朝向頂部 (MiniJoyC 方向) |
| **機身向左傾斜 (左側朝地)** | **$> +0.2g$** | 隨仰角而定 | 隨仰角而定 | 重力朝螢幕左側 (`ax` 為正！) |
| **機身向右傾斜 (右側朝地)** | **$< -0.2g$** | 隨仰角而定 | 隨仰角而定 | 重力朝螢幕右側 (`ax` 為負！) |

#### (2) 物理模擬 (沙粒/小球/水平儀) 之重力轉換公式
若要將 IMU 讀值轉換為螢幕上的**物件流動速度向量 $(gx, gy)$** 或氣泡位移，**必須將 X 軸取負號，Y 軸保持正號**：
```cpp
// 物理重力向量轉換公式 (直向 Rotation 0)
float gx = -ax; // 向右傾斜 (ax < 0) 時，gx 變為正值，推動小球/沙粒向右移動 (+X)
float gy = ay;  // 機身正立 (ay > 0) 時，gy 為正值，推動小球/沙粒向下墜落 (+Y)
```
- **氣泡水平儀 (Bubble Level - `SceneSensorLab`)**：
  ```cpp
  // 氣泡向傾斜方向滑動
  _targetBubbleX = -ax * 42.0f;
  _targetBubbleY = ay * 42.0f;
  ```
- **沙盤模擬 (Sand Toy - `SceneSand`)**：
  ```cpp
  float gx = -ax;
  float gy = ay;
  float gMag = sqrtf(gx * gx + gy * gy);
  if (gMag > 0.20f) {
      // 依 (gx, gy) 決定流動主方向與斜向滑落權重
  }
  ```

### 5.5 全域方向對照速查表 (Master Orientation Cheat Sheet)

### 5.6 螢幕轉向切換 (Rotation) 座標轉換防呆

若專案未來開發橫向模式 (`setRotation(1)` 或 `setRotation(3)`)，請特別注意：
**硬體上的 MiniJoyC 搖桿與 MPU6886 加速度計晶片是固定在硬體電路板上的，其物理軸向絕對不會隨螢幕 `setRotation()` 自動改變！**

若變更旋轉模式，請參考以下映射轉換原則：
- **`setRotation(1)` (橫向，頂部 MiniJoyC 朝左側)**：
  - 新螢幕寬高：240 × 135
  - 新螢幕 $X'$ 軸對應原來的 $+Y$ 軸
  - 新螢幕 $Y'$ 軸對應原來的 $-X$ 軸
  - 搖桿與重力必須做 90 度座標旋轉變換：
    - `joyX_new = joyY;`
    - `joyY_new = -joyX;`
    - `gx_new = gy;`
    - `gy_new = -gx;`
- **`setRotation(0)` (預設直向，寬 135，高 240)**：
  - 本專案所有遊戲（選單、俄羅斯方塊、沙盤、感測器實驗室、硬幣、猜拳等）**全數統一定義於 `setRotation(0)`**，不建議各場景私自切換旋轉模式，以確保所有驅動與體感演算法之一致性。
